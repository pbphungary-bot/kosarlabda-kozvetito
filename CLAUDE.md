## Architecture (big picture)
**Two independent static apps over one data folder.** `index.html` + `css/dashboard.css` (Közvetítőhub, vanilla JS inline) and `graphics/` (Graphics Studio) both read `data/*.json`, which the collectors keep fresh (Hunbasket is the primary source; a FullField.info Excel uploaded in the studio overrides team/player stats – with **three independent switches** per league (`enabledTeam`, `enabledPlayers`, `enabledCups` on `store.excel[lg]`, `Store.setExcelPart`; an old flag `enabled` is the fallback); European games come from FIBA or pasted eredmenyek.com text).

**Studio pipeline** (`graphics/js/`): `data.js` (`Store`: loads the JSON, club-scoped name matching via `clubs.js`, freshness, lazy sources like player pages/h2h via `loadLazy`) → `binders.js` (`bind*` functions turn store data into per-element values `{text|runs|src, source, missing…}` for one template type) → `templates.js` (geometry from the PSDs: elements with x/y/size/tracking/outline; dynamic builders `psBuild`, `rosterBuild`, `formTpl`, `h2hTpl`, `extraTpl`; registry `TEMPLATES`) → `engine.js` (deterministic Canvas 2D `render(canvas, template, values, assets)`: text fitting, image outlines, `framed` shapes, content/global transforms). `app.js` orchestrates UI, state (localStorage), overrides, the layout editor (`layout.js`: per-element dx/dy/size/scale/w/h, saved "alap" benchmarks), mobile/desktop switch, ZIP package (`package.js`); `panels.js` holds the self-contained side panels; `bgremove.js` runs in-browser AI background removal (ONNX Runtime in `vendor/ort`, model in `models/`). A binder can change element properties per value with `geom` (e.g. the key-players photo uses `fit: 'contain'`, `anchor: 'bottom'`); engine special cases: element ids `panel` (frame, exempt from the content move) and `photo`; a text element with `centerOn: <id>` is centred on the drawn box of an earlier text (head-to-head competition label under its date).

**Frames:** every graphic's panel is a `framed` element with id `panel` (court `assets/court/court.png` + outline, drawn by `drawFramed` in `engine.js`); the fixed rest of the PSD (titles, logo strip) is `templates/<id>/statics.png`, drawn on top of the panel (`staticsOnTop`). Panel geometry comes from `frames.js` (generated by `tools/psd_frames.py`); the compact Form / Head-to-head panels are built in `templates.js` (`panelFrame`). Resizing, moving and content-clipping all key off this element — see the frame rules in `DESIGN-SYSTEM.md`. Do not delete `templates/<id>/background.png`: it is no longer drawn, but `tools/psd_frames.py` derives `statics.png` from it.

**Live graphics** (`livestat`, `liveteam`, `liveleaders`): `live.js` decodes the netcasting feed and counts the stats (per player and team, per quarter, VAL via `efficiency`, `topByEff`); builders `liveTpl` / `liveTeamTpl` / `liveLeaderTpl` in `templates.js` (geometry in base units × a scale), binders `bindLiveStat` / `bindLiveTeam` / `bindLiveLeaders` (shared helpers `liveNameField`, `liveCellFns`, `liveHeaderValues`). Ticked stats, colours (hex via `normHex`), photo outline / shadow are saved in `sel.live` and **shared by the men's and women's tab through `LIVE_SHARED` in `saveState`** – add a new live setting there too. The engine gives images an optional `shadow` and an outline that can ignore faint halo pixels (`outlineAlphaMin`). The feed is only reachable through `tools/serve.py` (`/live`) or pasted text.

**Live on air (OBS), built 2026-11-26:** one fixed link per game, `graphics/overlay.html?game=<code>&token=…` (`js/overlay.js`, `overlay-params.js`): a transparent 1920×1080 canvas that reuses the studio's `bindLive*` / builders / `render`. The commentator's page `graphics/live.html` (`js/livelinks.js`) is the **on-air controller**: it POSTs the choice (graphic `livestat | liveteam | liveleaders | off`, ticked stats, player, colours / shadow, `teamLook`) to `serve.py` `/live-state`; the overlay polls it (1.5 s) and the feed (5 s, two independent timers) and switches by itself. `normOnAir` whitelists everything the server hands out. State is never kept in the page (a reload is harmless) and nothing is drawn on errors (last good picture stays). The feed writes ő / ű as `?`: `tools/mkosz_names.py` reads the right spelling from the mkosz.hu match page by player number, `applyOfficialNames` renames only when number AND letters fit. VAL = the netcasting page's formula (pts+reb+ast+stl+blk+fouls drawn − missed shots − turnovers; fouls and blocks against NOT subtracted), internal key still `eff`; FullField's EFF stays on the pre-game comparison. Team comparison looks (`teamLook()`): `outline` is the **default** (locked, 2026-11-27), `fill` the old one, `numbers` an experiment. Live settings of the studio (localStorage) and of the builder (server) are separate.

**Player lists and names:** every graphic that writes player names uses the owner's order rule – foreign players "Given SURNAME", Hungarians "SURNAME Given" (`displayName`, `isForeign`, nationality only exists on the team page's roster; the statistics rows have none, so `teamstatName` matches by name words). The player table (`teamstats`) builds its rows for the number of players shown (`TEAMSTATS_BUILDERS`, up to `TEAMSTATS_MAX`; more than the PSD's rows make rows tighter, same first / last row).

**Own jersey numbers (2026-11-27):** the feed / team pages often miss or repeat numbers (a data `0` = "no number"). The operator's numbers are stored **per player and team** in `sel.numOv[teamId][playerKey]` (player table key `<#>|<name>`, roster key `r|<page url>`), not per row: `teamstatPlayers` / `rosterPlayers(…, numOv)` sort by the effective number (own number wins, unknown sorts last in the table), `onFieldEvent` in `app.js` turns a number typed into a row's `rN.num` field into that player's number (and removes the row override), and the player table's list also has a number box per player. Never key such an override by row index: the rows re-sort.

**Pick bar and template order (2026-11-27):** the match and team selects are NOT in the sidebar any more but in `#pickBar` at the very top (`renderPickBar()` in `app.js`, called by `renderSelection`; the lines are dimmed when the current graphic does not use them; `--top-h` set from `#topStack` replaces the old fixed 54 px sticky offsets). The graphics list order is `TEMPLATE_ORDER` in `templates.js` (stable sort of the registry), the ZIP numbering is the order of `PACKAGE_ITEMS` in `package.js`.

**Live links (2026-11-27):** besides the game's main link (`?game=&token=`, follows the builder) the builder shows one link per live graphic (`?game=&show=livestat|liveteam|liveleaders`, `categoryLinkQuery`); `ownGraphic` in `overlay.js` forces that graphic but the settings still come from the server state. A game with no saved state (`rev` 0) gets the team comparison on air by default when it is picked in the builder (`firstPick` in `livelinks.js`); a saved choice, also *Nincs adásban*, is never replaced.

**Template ids** are `<type>-<men|women>`; types and labels are in `TEMPLATE_TYPES`. Adding a graphic means: builder in `templates.js` + registry entry, a `bind*` in `binders.js`, a branch in `app.js` (`autoValues`, selection panel, filename), optionally `package.js`, and tests (the e2e template count assertion must be updated).

**Tests** are hermetic: unit tests load `tests/fixtures/data` through `tests/helpers.mjs` (`loadStore`); e2e routes `/data/*.json` to the same fixtures. Update the fixtures (copy from `data/`) when a collector's output format changes. CI (`.github/workflows/tests.yml`) runs unit + Python + e2e on pull requests.

**Data conventions:** Hunbasket has one schedule page per competition (`<code>`, `<code>_ply` playoff, `<code>_cup` cup) and the netcasting code of a youth game keeps its old age limit (`hunu18_…` = U19 boys), so never derive the age group from a code; matching is club-scoped (`clubIdStrict`), never fuzzy across leagues; collectors use a polite User-Agent, are low-frequency, and `mkosz.hu`, `facebook` and `eredmenyek.com` are not reachable from the sandbox (use workflow probes or pasted data); `netcasting4.webpont.com` (live feed) **is** reachable (checked 2026-11-24, so live games can be tested here), `hunbasket.hu` too. `updated_at` in a data file only changes when the content changes, so an old stamp can still be a current file (some collectors also write a `checked` stamp). Shared dashboard notes use Supabase (table `matchup_notes`; reviewed read-only, see MANIFEST – the anon key can read/write every note; owner decided to leave it as is – do not change or re-raise it).

## Lessons learned (do not repeat these)
**Session hygiene**
- One feature per session and one pull request per feature; check whether the previous PR is already merged before pointing the owner at it. When a session gets long (many features, big context), say so and suggest a fresh session instead of pushing on; end every task by updating `MANIFEST.md` so the next session starts from facts, not memory.
- Before a big change, restate the rule in one sentence ("the court's upper/lower edge sits on the frame's borders, centred") and build exactly that. The frame work was done three times (baked backgrounds → shapes → PSD offsets → the owner's actual rule) because the rule came last. If the owner skips or denies a question, pick the sensible default, say which one, and continue.
- Look in the repo before asking for uploads or re-deriving things: the court, outline colours and stroke widths were already inside the PSDs the owner had uploaded.
- Do what was asked and verify it; put adjacent ideas into the "Open items" of `MANIFEST.md` instead of building them unasked.

**Tests and CI**
- CI runners are slower than the dev sandbox: never rely on fixed `waitForTimeout` after a state change, on window size or on pixel clicks near the viewport edge. Wait for a selector/condition, use a tall viewport for editor-handle tests, and retry clicking a spot that may be covered. Three browser-test failures only on GitHub (template list not rebuilt yet, panel not selectable, `fetch` keep-alive crash on server start) all came from this.
- A new workflow or dependency must be proven in a clean environment: the daily data-health job failed for two days because `bs4` was never installed there.
- Run `node --test tests/*.test.mjs`, the Python tests and the browser suite (**`node tests/e2e-parallel.mjs`**, ~3 min; the sequential `node tests/e2e.mjs` takes ~15 min in the sandbox) before every push, and confirm the CI result after pushing; a red CI is never left for the owner to find.
- After switching templates in a browser test, wait for the NEW template's own state before asserting (e.g. `fit === null`): the report of the previous graphic is still there for a moment and a slow CI runner reads it (the score bug check failed only on GitHub for this reason).
- "The numbers did not refresh": check the data file (`updated_at`, the commit of the collector) and the deploy first, then the **uploaded FullField Excel in the browser**, which overrides the Hunbasket data until it is switched off (that was the cause on 2026-11-25).
- When the owner says "I already uploaded it" (e.g. the broadcaster's score bug), look in the uploads / repo first: "the scoreboard" was the broadcaster's score bug in the owner's broadcast screenshots, not the netcasting web page I assumed. When a layout instruction can be read two ways (where the logos go), restate it in one sentence and show a picture before building more.

- A rule the owner already decided (name order, no arbitrary row limits) must hold in **every** graphic that shows the same thing: when a new or old graphic lists players, check `displayName` / the roster rule instead of copying names from the data rows (the player table showed foreign names in the data's order for weeks).

**Repo and data safety**
- Collectors overwrite `data/*.json` when run locally: run them on a copy, then restore (`git checkout -- data`); never `git checkout origin/main -- <path>` into the working tree and leave it staged.
- A blanket PSD extraction, a force-push or deleting files the owner uploaded are never acceptable without asking.
- Before replacing a pipeline stage (e.g. baked backgrounds → shapes), measure old vs new pixel-by-pixel and keep that check as a test.
- The sandbox cannot reach `mkosz.hu`, `facebook`, `eredmenyek.com` or the AI model/CDN hosts; probe from a workflow or use pasted data instead of guessing.

**Live system, hosting and CI (2026-11-26/27)**
- Test stubs: Playwright's glob `**/live?*` also matches `/live-state?…` (`?` matches any character, the dash too): stub the relay with a predicate (`u => u.pathname === '/live'`).
- The e2e clock is frozen: code under test must not do `Date.now()` arithmetic (the overlay's "feed due" check never fired). Use independent timers; in tests wait for real signals (`window.__overlay.drawn()` / `draws()`), never for a fixed sleep or a status text that still belongs to the previous graphic.
- Async state loaded after a user click must never overwrite that click (builder `touchSeq`); found by the e2e, not by reading the code.
- **Verify a theory before sending the owner to a third party:** DNSSEC looked like the cause of "Server failed", the Verisign analyzer showed no DS record. The real cause was one network's plain DNS (fix: DNS over HTTPS; OBS needs the Windows DNS setting, not Firefox's).
- Secrets: the Cloudflare tunnel token and the access key must never be pasted into the chat or committed; the owner pasted the token once (rotate it via "Rotate token"). Never touch `playbyplay.hu` DNS (the owner's e-mail runs on it); the live address uses the spare domain `livegolf.eu`.
- Cloudflare route: `http://127.0.0.1:8000` (not `https`, not `localhost`, which can resolve to IPv6 on Windows); never run the dashboard's `service install` (the launcher starts the tunnel).
- The owner may merge a pull request while its CI is still running: before pushing "to the PR", check its state; commits pushed after the merge need a new PR (#48 → #49). A bot's deploy-preview comment needs no action.
- Verified formulas beat remembered ones: VAL was checked player by player against the netcasting page (an unchanged player with a block against decided it), not derived from the textbook formula.

**Session of 2026-11-27 (do not repeat these)**
- **The central computer runs a long-lived process that updates only at start.** "Photos / logos missing", "it crashed again": first make sure they run the newest version (restart; the `Indítás kész …` line and `.live-server.log` prove it). An old process can keep port 8000 and make the new start quit silently; give the exact PowerShell commands (`MANIFEST.md` 5d), never during a broadcast. It works in the sandbox because the sandbox always runs the newest code: do not conclude "works" from that.
- **Find the control the owner actually uses.** The first version of the own jersey numbers only sorted via a new box in the player list; the owner types into the row field of the Mezők tab and called it sloppy. Look at the owner's screenshot for the field they used and cover that path in the test (`onFieldEvent`).
- **Measure what the owner measures.** Line gap: my "white pixels only" measure (18 px) was not the owner's Photoshop number (42 px, a different layout state); accent letters (É, Ő) poke into the gap. Say how a number was measured, show a picture, ask once.
- **Branch hygiene with squash merges.** After a PR is merged: `git fetch`, `git checkout -B <session branch> origin/main` (carry uncommitted work with `git stash`), push with `--force-with-lease=<branch>:<old sha>` (the branch only holds merged history). Never push under a new branch name (the first push of the day went to the wrong branch). The stop hook's "N unpushed commits" afterwards are `main`'s own commits (merge + automatic data refreshes): nothing of yours, do not push them. Only the owner and the assistant act on GitHub: a merge you did not make is the owner's.
- **Sequential e2e checks share the test server's state.** `/live-state` is kept across checks: a check that changes what is on air must use its own game code (the builder check uses `whun_135563`, the category-link check `whun_135570`), otherwise the "new game defaults to the team comparison" check fails.
- **A check that passes alone and fails only in the 4-process run is a timeout, not a flake.** Wait for the real condition with a generous limit (the crest-loading wait got 60 s); never skip the check.
- **Docs-only and tooling PRs still run the full local sets** (unit, Python, parallel e2e); the owner wants every push proven.
